# Short-form dialogue format

Use this reference for a new character-led explainer or when the user requests the FSP/Peter-and-Stewie style. User instructions and an existing project's established style take precedence.

## Script target

- Audience: junior-to-mid practitioners unless the user specifies otherwise.
- Target: 300–380 words; hard cap 430.
- Structure: 6–7 exchanges, usually 12–14 lines.
- Questioning beats: roughly 5–25 words.
- Explaining beats: roughly 25–60 words.
- Use one sharp hook, not a survey of the entire topic.

## Writing rules

1. Verify important factual claims against a primary source.
2. Use concrete numbers, names, versions, and mechanisms instead of vague claims.
3. Introduce unfamiliar terms inline by mechanism. Explain what happens, then give it a name.
4. Make every question or pushback the natural consequence of the previous answer. Generic reaction lines are filler.
5. Let each explanatory beat answer one main question.
6. Engineer punctuation for speech. Remove unnecessary commas and use periods only where a pause should be audible.
7. End with a reframe: the final answer should change how the viewer sees the broader topic rather than repeat the preceding facts.

## Review checks

- Flow: could each response only sensibly follow the line before it?
- Vocabulary: is every non-obvious technical term explained?
- Evidence: can every number and specific factual assertion be sourced?
- Brevity: can any sentence be removed without losing the mechanism?
- Speech: does it sound natural when read aloud?
- Close: does the last line reframe instead of summarize?

## Visual hierarchy

For a 1080 × 1920 portrait composition:

1. Moving background video fills the canvas and stays muted.
2. Optional b-roll occupies the upper region around 88% width × 42% height, centered near 28% from the top.
3. Captions are horizontally centered around the vertical midpoint, above the character's face.
4. The active character is bottom-anchored at roughly 37.5% of player height and enters from its assigned side.

Keep captions readable before adding visual density. The opening hook should have a clear visual, but later conversational beats can rely on the background, captions, and character.

## B-roll policy

Use this order:

1. Images and diagrams from the primary source.
2. Official screenshots, product images, photographs, charts, or logos.
3. A reaction GIF/video for a genuinely emotional beat.
4. A generated infographic for an abstract mechanism with no suitable real asset.

Reject assets that cannot be understood within one second, misleading generated evidence, unreadable diagrams, generic glassy stat cards, and visuals that merely repeat the caption text.
